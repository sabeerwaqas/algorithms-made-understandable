# 7. Revision and self-assessment

**VU LMS index:** 47–48

Use revision to test understanding, not to count how many pages you reread.

## Revision method

For each topic:
1. Close the guide and write the problem definition from memory.
2. State the core idea in three or four sentences.
3. Dry-run one small input.
4. Write the algorithm or recurrence from memory.
5. Derive time and auxiliary-space complexity.
6. Name an edge case or condition under which the method fails.
7. Reimplement a selected algorithm without copying.

## Topics to revisit

- Algorithm model, primitive operations, worst-case analysis, and asymptotic notation.
- Divide and conquer, recurrences, Merge Sort, and Quick Sort.
- Selection, heaps, and sorting lower bounds.
- Counting, Bucket, and Radix Sort assumptions.
- DP states and transitions for Fibonacci, Edit Distance, Matrix Chain Multiplication, and 0/1 Knapsack.
- Greedy-choice conditions for coin change, Huffman coding, activity selection, and fractional knapsack.
- Graph representation, BFS, DFS, timestamps, cycles, topological sorting, SCC, MST, and shortest paths.
- P, NP, reductions, graph coloring, SAT, and independent set.

## Self-assessment

You are ready to move on from a topic when you can do all of the following without notes:

- [ ] Explain the problem and why the algorithm exists.
- [ ] Work through a small example correctly.
- [ ] Write the main algorithm steps or recurrence.
- [ ] Explain why the algorithm is correct at a high level.
- [ ] Derive its time complexity.
- [ ] State auxiliary-space usage.
- [ ] Identify important assumptions and edge cases.
- [ ] Implement the core logic independently.

## Pre-assessment

Do not mark a topic complete because you recognized the answer. Mark it complete after you can explain and reproduce the reasoning.
