# Contributing

The goal is to make an algorithm easier to understand, not to increase the number of files.

## Useful contributions

- Correct an inaccurate statement or complexity bound.
- Add a small worked example that exposes a confusing step.
- Improve a diagram or animation so it explains a real state change.
- Add an edge-case test.
- Add a Java implementation that follows the documented assumptions.
- Improve image alt text, contrast, and labels.

## Before submitting

1. Read the relevant topic guide and check the course index in the root README.
2. Prefer a focused change over a large rewrite.
3. Do not copy VU handout pages, third-party notes, or another repository's solution.
4. Add external references to SOURCES.md.
5. Explain any algorithm variant or assumption that affects correctness.

## Standard for a new algorithm page

Include the problem and why it matters, input and expected output, core intuition, a worked example, steps or pseudocode, correctness reasoning or an invariant, time and auxiliary-space complexity with a derivation, limitations, edge cases, and self-check questions.

Code should be readable and tested. An implementation without an explanation is not enough for this repository.

## Visual standards

- Use SVG for static diagrams.
- Use GIF only when showing a sequence materially improves understanding.
- Give every image meaningful alt text.
- Use original assets or assets with compatible licences.
- Do not animate merely for decoration.
